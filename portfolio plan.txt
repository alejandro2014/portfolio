2️⃣ Microservices breakdown
🔐 1. API Gateway / Auth Service (Spring Boot)
Responsibilities
  User authentication (JWT)
  Request routing
  Rate limiting
  User isolation (multi-tenant safety)
Tech
  Spring Security
  JWT
  Optional OAuth (Google login later)

🖼️ 2. Photo Service (Spring Boot)
Responsibilities
  Receive photo uploads
  Validate image format
  Send image to:
    Image optimization service
    AI service
  Store processed images
  Track processing status
Key endpoints
  POST /photos/upload
  GET /photos/{id}
  GET /photos/{id}/download
Notes
  Async processing via message queue (RabbitMQ / Kafka optional)
  Stores only references, not embeddings

🧠 3. AI Service (Python)
Responsibilities
  Face detection
  Embedding extraction
  Face clustering / recognition
  Incremental learning (no retraining)
Stack
  InsightFace
  FastAPI
  NumPy
  FAISS (optional, for scaling)
  Endpoints
    POST /analyze-image
    Input: image
    Output:
    {
      "faces": [
        {
          "bbox": [x1, y1, x2, y2],
          "embedding_id": "uuid"
        }
      ]
    }

    POST /recognize
    POST /enroll-person
Important design decision👉 Store embeddings in AI service, not in Postgres directly(Postgres only stores references + metadata)

3️⃣ Image processing pipeline
Upload →
  Validate →
    Optimize (JPEG lossy, visually lossless) →
      Thumbnail generation →
        AI analysis →
          Metadata persistence

Optimization
MozJPEG / libjpeg-turbo
Quality ~75–85
Resize max edge (e.g. 4k)

4️⃣ Face recognition lifecycle
🧠 Embedding strategy
Normalize embeddings
One-to-many per person
Optional: store centroid embedding
👤 User tagging flow
User sees detected faces (bounding boxes)
Tags face as:
Existing person
New person
AI service:
Adds embedding to that identity
Updates centroid
🔍 Recognition logic
Cosine similarity
Threshold-based matching
Fallback to “Unknown”
